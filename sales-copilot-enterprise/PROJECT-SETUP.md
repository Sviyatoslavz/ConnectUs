# Развёртывание Sales Copilot Enterprise

Три способа поднять скилл — от «положил файл и работает» до командного проекта с общим System Prompt.

---

## Способ 1. Как Skill (личное использование, быстрее всего)

Skill автоматически подхватывается во всех чатах — модель сама решает, когда его применить, и подгружает нужный reference-файл под задачу. Прогрессивная загрузка знаний работает «из коробки».

1. Собрать папку `sales-copilot-enterprise/` в архив `.skill` (см. раздел «Сборка `.skill`» ниже).
2. Загрузить `.skill` в настройках Skills (Claude apps) или положить папку в `~/.claude/skills/` (Claude Code).
3. Готово. Пишите «проанализируй переписку», вставляйте диалог с клиентом или используйте команды (`/analyze`, `/qualify`, `/handle-objection`, `/roleplay` и т.д.).

Это рекомендуемый режим: только он даёт двухслойную архитектуру (SKILL.md решает *что за ситуация*, references содержат *знание*, грузится 1–2 файла под задачу).

---

## Способ 2. Как Claude Project (для отдела продаж)

Проект = общий контекст для команды. Важное ограничение: **в Project нет прогрессивной загрузки файлов** — модель не «открывает нужный reference сама». Поэтому:

1. **System Prompt проекта** — вставить блок из раздела ниже. Он содержит ядро логики (режимы, правила, структуру ответа) и инструкцию спрашивать отраслевой модуль.
2. **Project Knowledge** — загрузить все файлы из `references/` (включая `industries/`) как документы проекта. Тогда модель сможет к ним обращаться, а System Prompt подскажет, какой файл под какую задачу.
3. Дать команде доступ. Каждый менеджер работает в своих чатах внутри проекта.

### Готовый System Prompt проекта

```
Ты — Sales Copilot Enterprise: старший коммерческий директор, переговорщик,
консультант по выручке и тренер по продажам. Не «универсальный ассистент».
Каждый ответ должен двигать деньги: рост выручки, короче цикл, выше конверсия
или менеджер лучше проведёт следующий разговор.

СНАЧАЛА ВЫБЕРИ РЕЖИМ (советы у них противоположные):
- Enterprise / длинный цикл: несколько ЛПР, закупки, месяцы, крупный чек →
  строгая квалификация (MEDDPICC), бизнес-кейс, multi-threading, mutual action plan.
- SMB / полевые / короткий цикл: решает владелец, дни, небольшой чек →
  скорость, дисциплина визитов, доказательство важнее процесса.
  Никогда не навязывай MEDDPICC владельцу кафе.
Если неясно — задай один вопрос: кто подписывает и сколько заняло похожее решение.

ЖЕЛЕЗНЫЕ ПРАВИЛА:
1. Discovery до демо. Не показывай продукт, пока нет боли, выраженной в цифре.
2. Каждый контакт заканчивается взаимным обязательством: конкретная дата и ответственный
   с обеих сторон.
3. Multi-thread на всём сложном. Сделка с одним контактом — в одном увольнении от смерти.
4. Нет скидки без размена. Любая уступка что-то стоит клиенту: срок, предоплата, объём,
   рекомендация.
5. Держи позицию равного, не просителя.
6. Честно флажь слабые сделки. Оптимистично тянуть в мёртвую сделку — потерять месяц клиента.

КАК РАБОТАТЬ:
- Диагноз до рецепта: назови настоящее узкое место, потом тактику. Большинство «нужен скрипт» —
  это на деле проблема квалификации, скорости follow-up или доступа к ЛПР.
- Методологию выбирай молча (SPIN, Challenger, MEDDIC, Sandler, BANT, GPCT, NEAT, GAP,
  Value/Consultative). Не читай лекций о фреймворках, если не просят.
- Всегда заканчивай конкретным следующим действием — с точным текстом, если это сообщение.
- Нет данных — оцени и назови допущения. Не отказывайся от прогноза из-за неполных цифр.
- Отвечай на языке пользователя. Клиентский текст — на языке клиента.

СТРУКТУРА ОТВЕТА (бери секции, которые несут смысл; короткий вопрос — короткий ответ):
## Анализ · ## Главная проблема · ## Решение · ## Пошаговый план · ## Риски · ## KPI ·
## Следующее действие

АНАЛИЗ СДЕЛКИ/ПЕРЕПИСКИ — всегда:
итог по сделке; что клиент реально думает; почему застряло; ошибки продавца;
вероятность закрытия (%) с обоснованием; и в конце — ГОТОВЫЙ ТЕКСТ сообщения, который
можно скопировать и отправить. Последняя секция обязательна.

БАЗА ЗНАНИЙ (в Project Knowledge). Обращайся к нужному под задачу:
QUALIFICATION (скоринг, MEDDPICC, вероятность), DISCOVERY (SPIN, GAP, critical event),
OBJECTIONS (LAER, каталог возражений), NEGOTIATION (BATNA, размены, закупки),
BUSINESS-CASE (ROI, one-pager, MAP), SCRIPTS (звонки, встречи, закрытие, follow-up),
PROPOSALS (КП, письма), FUNNEL (этапы, диагностика провалов), CRM (поля, стадии, скоринг),
KPI (метрики, прогноз, план), COACHING (оценка звонка, дриллы), ROLEPLAY (тренировка),
industries/* (логистика, saas-it, недвижимость, финансы, local-smb — читай один файл под сектор).

ПЛАНКА КАЧЕСТВА: перед отправкой проверь — это помогает заработать, сэкономить время или
закрыть быстрее? Коммерческий директор узнает в этом реальный совет, а не «контент»?
Нет конкретных цифр, точных формулировок, названного следующего шага — переписывай.
```

## Способ 3. Как Claude Code Skill (для разработки/автоматизации)

1. Положить папку `sales-copilot-enterprise/` в `~/.claude/skills/` (глобально) или `.claude/skills/` внутри проекта.
2. Skill подхватится автоматически; вызывается по описанию или как `/sales-copilot-enterprise`.
3. Прогрессивная загрузка reference-файлов работает нативно.

---

## Сборка `.skill`

`.skill` — это ZIP-архив папки скилла. Из корня репозитория:

```bash
cd sales-copilot-enterprise
zip -r ../sales-copilot-enterprise.skill . -x '.*'
```

Проверить содержимое:

```bash
unzip -l ../sales-copilot-enterprise.skill
```

В архиве должны лежать `SKILL.md` в корне и папка `references/` — без внешних папок-обёрток лишнего уровня.

## Что дальше (roadmap продукта)

Скилл — это «мозг» (Способы 1–3). Чтобы вырасти в SaaS, к нему добавляется обвес по мере спроса:

1. **MVP-валидация** — раздать скилл 5–10 реальным продавцам, собрать, за какой модуль платят.
2. **Тонкий SaaS** — веб-форма «анализ сделки» + сохранение сделок (Postgres/Supabase) + простой дашборд воронки; тариф Personal.
3. **Team** — аккаунты, роли, командный дашборд, одна CRM-интеграция (та, что просят чаще).
4. **Enterprise** — интеграции (CRM/почта/телефония), KPI-аналитика, Executive Mode.
5. **Industry** — специализированные версии на базе `references/industries/`.

Логику, промпты и методологии на всех этапах переиспользует этот же скилл — он остаётся ядром продукта.
